## 1. 背景と動機

RecursiveCompressor 系のモデルは自然言語を学習できたが、生成が進むと特定の話題語に
執着する現象（`text/oil.txt` の「オイル」反復）が解消できなかった。copying-memory
ブランチで位置情報（chunk_pos_emb → CausalConv）を整備しても執着は残り
（[copying-memory-branch-changes.md](copying-memory-branch-changes.md)）、
「固定の学習ベクトル（initial_context / compressor_query / pos_emb）を残差ストリームに
繰り返し注入する構造」自体との相性を疑って、main のアーキテクチャには手を入れず
新設計に切り替えた。

LogKV の設計方針:

- **kv はすべて内容由来**。学習済み固定ベクトルの注入なし、位置埋め込みなし
- 各位置が参照する kv の数を **O(C·log L)** に抑えつつ、受容野は全系列
- 逐次推論の hidden state も **O(C·log L·d)**（系列長に対して対数）

## 2. アーキテクチャ定義

### 2.1 圧縮階層

q, k, v = 線形射影（bias なし）。**マルチヘッド**: ヘッドをバッチ次元に折り畳んで `(B·H, L, d_head)` とし、階層圧縮と窓 attention のコア（`_attend`）をヘッドごとに独立に 通した後、ヘッド結合 → 出力射影 `lo`（bias なし）。hidden のバッチ次元も B·H になる。スケールは d_head^(−1/2)。`Compressor` はチャンク
（長さ C = chunk_size）を **チャンク末尾の q をクエリとした attention プーリング** で
1 要素に圧縮する（q_out = 末尾 q、k_out / v_out = softmax(q_out·kᵀ) による凸結合）。

レベル i の列（サブユニット = C^i トークンの要約）を C 個ずつチャンク化して圧縮すると
レベル i+1 の列になる。完成したチャンクは上位へ渡し、各レベルには C 未満の未完成部分だけを
保持する。最上位の残り列も保持し、全系列を受容野に含める。

### 2.2 attention のスロット意味論

位置 s のクエリについて、レベル i（サブユニット長 C^i、ブロック長 C^(i+1)）の
ブロック番号を u、ブロック内のサブユニット番号を j とする:

- スロット c < j → 自ブロック u の完成済みサブユニット c
- スロット c ≥ j → 無効（前ブロックからの補充はしない）

有効スロット数は各レベル j 個（最大 C−1）。過去 [0,s) を重複も欠落もない区間に分割する。
例えば C=4 の位置4ではレベル1の要約0〜3のみ、位置5ではそれにレベル0のトークン4が加わる。

全レベルのスロットを連結して **単一の softmax** で正規化し value を加重和する。
`self_slot=True` なら現在トークンの k/v を別途1スロット追加する。無効なら系列先頭の出力は0。

### 2.3 レベル減衰ロジットバイアス（3f7cc40、§5.3 参照）

レベル i のロジットに `i · log(1/C)` を加算する（スロット重みに C^(−i) を掛けるのと
等価）。パラメータフリー。
重複除去後も係数は維持するが、現在は粗い階層へのペナルティとして働く。旧構造の
多重計上補正という根拠（§5.3）は適用されず、新構造での有効性は再検証が必要。

### 2.4 サブチャンク間の相対位置logitバイアス

`relative_position_bias=True` で、全レベルの有効スロットに次の補正を追加する。
コードのレベル番号は最下位がi=0（提案図の「レベル1」）。

```text
j = floor(s / C^i) mod C
distance = j - c - 1                  # 有効スロット c < j では0以上
logit = q·k / sqrt(d_head) - i*log(C) - distance*log(C)/(C-1)
```

C=4なら追加係数はlog(4)/3で、レベルi=1では同じ4トークンのサブチャンク内で一定。
直前の完成済みサブチャンクへの追加減衰は0、それより古いスロットは距離に応じて減衰する。
内容logitが同じとき、非正規化重みは `C^(-i-distance/(C-1))` に比例する。
既存のcausal mask・重複なし参照・全レベル共通softmaxを維持する。
self slotのバイアスは0。このオプション単独では圧縮用attention poolingは変更しない。
`learnable_decay` / `level_amplify` を使う場合も追加の相対項は固定のまま。

追加の学習パラメータやhiddenは不要。C=2では各レベルの有効スロットが最大1個なので、
追加距離は常に0となる。位相埋め込みと同等の表現力を保証するものではなく、特に
圧縮済みチャンク内部の順序保持への効果は実験で確認する。

互換性のためConfigのデフォルトはFalse。既存チェックポイントの挙動は変わらない。
位相埋め込みを置き換える実験では `--relative-position-bias` を指定し、
`--phase-emb` は付けない（`phase_emb=False`）。既存の固定レベル減衰は引き続き有効。
Copying / Selective CopyingとLMの両学習CLIで同じオプションを利用できる。

### 2.5 Compressorの位置減衰

`compressor_decay=α` を指定すると、圧縮のsoftmax直前に次を適用する。
圧縮は末尾Queryを用いるため、古い順の距離は `[C-1, ..., 1, 0]`。

```text
compression_logit[c] = q_last·k[c] / sqrt(d_head) - α*(C-1-c)
```

KとVはこの同じ重みで圧縮し、q_outは従来どおり末尾q。既存のretrieval側の相対項や
固定レベル減衰とは独立した設定。レベル内で共通の `i*log(C)` を圧縮softmaxに加えても
相殺されるため、圧縮側には距離項だけを入れる。

- `--compressor-decay 0.46209812037329684`: C=4の基準 `log(C)/(C-1)`。
  内容logitが等しい場合、最古／最新の重み比は1/4。半分の係数なら1/2
- `--learnable-compressor-decay` も指定すると `α_h=softplus(raw_decay_h)`。
  正の `compressor_decay` を初期値の最大値とし、Hヘッドを最大値〜その1/4の等比列で初期化
  （H=1は最大値）。各Transformer層・ヘッドで別パラメータを持ち、全圧縮階層で共有。
  d512/8 heads/2層なら追加16パラメータ。初期化は乱数を消費しない
- デフォルトは `compressor_decay=0.0, learnable_compressor_decay=False`。
  この場合は追加のパラメータがなく、従来の出力・勾配と一致。負・非有限な係数と、
  学習可能版の初期値0は拒否する
- 複数チャンクのバッチは `(batch, head, chunk)` の順で平坦化される。
  `Compressor.forward(..., num_chunks=N)` にNを渡し、ヘッドと係数を対応させる。
  hiddenの形式と対数サイズは変わらない。既存の実行中hiddenを新しい設定へ流用せず、
  設定変更後は `hidden=None` から始める
- 有効時はlogit補正・softmaxを最低fp32で行い、K/Vとの積の前に重みのdtypeを合わせる。
  fp64は維持し、bf16重みのautocastなし推論にも対応する

この補正はK/Vの順序による非対称性を圧縮に導入するが、同一valueの正規化加重平均が
同一になる性質は残る。固定係数が大きいと再帰的な圧縮で古い情報への減衰が重なるため、
係数と記憶精度の関係は実験で確認する。
位相埋め込みを使わない実験では `--phase-emb` を付けず、retrievalの相対補正を併用するなら
`--relative-position-bias` を指定する。

検証: 221 tests passed。独立した圧縮・retrieval参照とのfp64出力・勾配一致、C=2/3/4、
ヘッドとチャンクの対応、任意分割・逐次推論、因果性、再計算、bf16、保存読込を含む。

### 2.6 階層内の局所RoPE（実験オプション）

`--retrieval-rope`は読み出しlogitを`q^T R(c−j) k / sqrt(d_head)`に変更する。
`--compressor-rope`は圧縮logitを`q_last^T R(c−(C−1)) k_c / sqrt(d_head)`に変更し、
回転前のK/Vをその重みで混合する。どちらも保存K/Vには回転を直接適用しない。
基数10,000、全head次元の隣接ペアを使用、角度は階層内の子位置差のみ。
偶数head次元が必要で、三角関数と回転は最低fp32、内積前に元dtypeへ戻す。
既定値false、学習パラメータ・hidden形式・無効時の乱数消費に変更なし。
phase2・固定レベル減衰を維持した[設計と比較実験](logkv-phase2-rope.md)を参照。

## 3. 実装上の知見

### 3.1 step() が唯一の実装、forward/predict は委譲

`step(x, hidden)` は任意長セグメントを **トークンループなし** で一括処理する
（ループはレベル数 O(log L) のみ）。成立する根拠は次の 3 性質:

1. **ブロック整列のスロット選択をベクトル化できる**: `q_sub = s // C^i`、`j = q_sub % C`
   として `a_c = q_sub − j + c`、有効条件は `c < j`。C−1個の候補をgatherし、未完成部分を
   マスクする。前ブロックのスロットは参照しない
2. **窓内要素は必ずクエリより前に完成する**（要素 a ≤ q_sub−1 の完成トークンは
   クエリより前）ので、階層状態をレベル一括で先に更新してから全クエリの attention を
   まとめて計算しても causal を破らない
3. **必要な過去は cur だけでカバーできる**: セグメント最古クエリの自ブロック先頭は、
   呼び出し開始時に保持している未完成チャンクの先頭と一致する。これと今回到着する要素を
   連結すれば全クエリの参照先を網羅できる

hidden は `(levels, offset)`。`levels[i] = [cur_q, cur_k, cur_v]`
（構築中チャンク <C 要素のみ）、`offset` は処理済みトークン数（絶対位置の復元に必要）。
呼び出し側の hidden は破壊しない。保持する小さなスライスはcloneし、推論時に元セグメント
全体のストレージを保持し続けないようにする。

forward は `step(x)` の一発呼び出し、`predict(x (B, d), hidden)` は 1 トークン版
（RecursiveCompressorAttention と同インターフェース）。

### 3.2 等価性の担保

forward が step 委譲になると step==forward のテストが自明化するため、当初の並列実装
（レベル構築 → ブロック整列 gather）を [test_logkv.py](../test_logkv.py) の
`reference_forward` に独立オラクルとして保持している。step / 分割 step / 1 トークン
predict 連鎖は fp64 で参照実装と **機械精度（<1e-12）** で一致する。意味論を変更する
とき（レベル減衰など）は参照実装にも同じ変更を入れる。
重複除去では参照実装も自ブロックの `c < j` のみに更新した。さらに実際にgatherされた
要約の由来をone-hot keyで追跡し、各過去位置がちょうど1回現れることを独立に検証する。

### 3.3 LM 化

`LogKVBlock` = pre-norm の標準ブロック（`x += LogKV(RMSNorm(x)); x += FFNSwiGLU(RMSNorm(x))`）。
`LogKVLM` は RecursiveCompressorLM と同じ骨格（embedding std 0.02、RMSNorm、head、
all-PAD ラベルの NaN ガード、HF `generate()` 用に per-layer hidden を `past_key_values`
として opaque に持ち回り、Cache ラップ無効化）。greedy `generate()` が step+argmax の
逐次生成と完全一致することをテストしている。

### 3.4 online softmax と attention の再計算（VRAM 削減）

`_attend_levels` はレベルごとに `(m_i, l_i, acc_i)`（スロット内最大ロジット・分母・value
の分子）を計算し、標準の再スケーリングで逐次マージする **online softmax**。全レベルの
slot を連結した `(B·H, L, C·levels, d_head)` テンソルを作らない。さらに attention 部全体を
`torch.utils.checkpoint`（非 reentrant）の 1 領域にし、autograd が保持するのは各レベルの
ctx（合計 ≈1.33 L·d）と出力だけで、gather と部分 softmax は逆伝播時に再計算する
（`LogKV.recompute_attention`、推論時は無効）。

設計上の注意点:

- online softmax の統計量は `promote_types(logits.dtype, fp32)` で累積（bf16 autocast 下は
  fp32、fp64 入力は fp64）。有効スロットのない行は `m = −inf` のまま持ち、マージの基準値
  だけ 0 に差し替える（0 の寄与に任意の基準値を使うのは安全だが、空レベルに 0 を
  そのまま使うと有限ロジット行の基準が狂いアンダーフローする）
- レベル単位の checkpoint では fp32 の部分和 `acc_i` とマージ中間 `(L, d)` が外側に残り
  削減が 15.9→13.0 GiB に留まった。**attention 部全体を 1 領域** にして 10.2 GiB
- 数値影響: fp64 で参照実装と機械精度一致、checkpoint 経路と非 checkpoint 経路は出力・
  勾配ともビット一致。実データ 8 サンプル × 2047 トークン（8H checkpoint-5000）で
  fp32 同士の logits 平均差 1.6e-6（loss 差 6e-8）。bf16 では fp32 真値からの距離が
  旧 9.02e-3 / 新 8.99e-3 と同等（loss 差 2.05e-4 vs 1.61e-4）で、新旧の bf16 間の差は
  各々の bf16 丸め誤差の範囲内
- 再計算コストは attention の gather/einsum が安価なため小さく、28 スロット連結の巨大
  cat/einsum が消えた分で相殺され、同 batch でも旧実装より速い

### 3.5 訓練インフラ

LogKVLM は 1 GPU に収まるので **DDP データ並列**（`torchrun --nproc_per_node=6
train_logkv.py`）。既存の mmap キャッシュ（`hf_cache/mmap/ctx2048/`, pretrain）を
そのまま利用。Muon（2D 隠れ層）+ AdamW（embedding/head/1D）、線形 warmup、bf16 autocast、
勾配蓄積、control.cmd、`--resume latest`、TensorBoard（`tensorboard/logkv-pretrain/`）。
rank 0 が `--sample-interval` ごとに固定日本語プロンプト 3 種から生成し `samples.log`
に追記する（文法獲得の目視確認用）。

実測（d1024 / d_ff 3072 / 16 層 / C=4 / ctx2048、シングルヘッド 294M パラメータ。
8 ヘッド版は `lo` の分 +17M）:

- 旧 attention 実装（全レベルの slot を連結して 1 回の softmax）: batch 2/GPU で 16 GiB、
  **batch 4 は OOM**。支配項はレベルごとの slot gather `(L, C·levels, d)` と連結コピーの保存
- 約 4,000 tok/s/GPU、6 GPU DDP 実効 **約 15k tok/s**（1000 ステップ ≈ 50 分）
- 8 ヘッド版（310M）: batch 2/GPU で 15.9 GiB、約 4,260 tok/s/GPU（シングルヘッドと同等）

**online softmax + attention 部の activation checkpoint（§3.4）導入後**（8 ヘッド、1 GPU 実測）:

| batch/GPU | 旧実装 | 新実装 |
|---|---|---|
| 2 | 15.9 GiB / 4,260 tok/s | **10.2 GiB** / 4,840 tok/s |
| 4 | OOM | 16.3 GiB / **5,725 tok/s** |
| 6 | OOM | 22.5 GiB / 5,865 tok/s |

## 5. 実験 2: 話題執着の同定と対策

### 5.1 症状（checkpoint-6277、1024 トークン生成）

3 プロンプトすべてで「序盤は正常 → 序盤に出た内容語が支配的になる → 末尾でその語の
反復に崩壊」。生成テキストを 4 等分した出現回数:

| プロンプト | 語 | Q1 | Q2 | Q3 | Q4 |
|---|---|---|---|---|---|
| 日本の首都は | 車 | 24 | 29 | 12 | 1 |
| | 形 | 0 | 17 | 27 | **142** |
| 昔々あるところに | 酒 | 14 | 24 | 40 | **54** |
| 人工知能とは | 生物学 | 21 | 25 | 9 | 1 |
| | 分子 | 2 | 0 | 30 | **68** |

序盤語の頻度が単調増加し、末尾は「形形形形…」「分子の分子の分子…」。支配語が
車→形、生物学→分子と **乗り換わりながら** それぞれ増殖する。EOS で終端した生成は
0/3（執着の正帰還で文書を終えられない）。

### 5.2 原因仮説: レベル横断の多重計上

Compressor は softmax プーリングなので、**顕著なトークンの value は希釈されずに上位
レベルへ生き残る**。距離 d のトークンはレベル i₀ ≈ log_C d から最上位までの
約 (log L − log d) 個のスロットに **全濃度で同時に存在** し、softmax 内で実出現回数の
log 倍に多重計上される。これが「出現 → スロット占有率増 → attention が引かれる →
再出現」の正帰還を増幅する。最上位スロットは一度完成すると以後の全クエリから見え続ける
ため、序盤内容の引力が永続する。予測「序盤語が進行とともに増える」は 5.1 で確認された。

### 5.3 対策: レベル減衰ロジットバイアス

レベル i のロジットに `i·log(1/C)` を加算（重み C^(−i)）。同一トークン由来のレベル横断
コピー群の重みが `C^(−i₀)(1 + 1/C + 1/C² + …)` の等比和に潰れ、**実質 1 回分の計上** に
正規化される。実際に何度も出現した語が高頻度に見える「正しいカウント」は保存される。

副次的性質:

- 距離 d の最安アクセスレベルが log_C d なので **~1/d のべき乗則 recency prior** を
  誘導する（パラメータフリー・スケール不変、固定位置埋め込みを避ける方針と整合）
- 最上位スロットの重みが C^(−top) ≈ 1/L に減衰し、序盤内容を思い出すには内容マッチで
  log L 程度のロジット差を跳ね返す必要がある形になる

### 5.4 効果（run `d1024-l16-leveldecay`、同条件で 5000 ステップ、checkpoint-5000）

| | 補正なし（6277 步） | レベル減衰（5000 步） |
|---|---|---|
| 1024 トークン完走時 | 3/3 が単一語反復に崩壊 | 崩壊はデータ様式的な反復 2 件のみ |
| 序盤語の四分位推移 | 全サンプルで単調増殖 | 日本 1→1→0→1、社会 2→1→0→1 と平坦 |
| EOS 自然終端 | 0/3 | **8/9**（seed 0–2 × 3 プロンプト） |
| 5000 步 EMA loss | 3.62 | 3.69 |

seed 1・2 は全プロンプトで一貫した短い文章を書いて `</s>` で閉じる。**文書を「書き
終えられる」ようになったこと自体が、序盤内容の永続的引力が消えた証拠**。

残った症状（seed 0）: 「衆議院議員」のリスト反復（議員 3→4→9→18。ただし Wikipedia
の一覧・フッター様式の模倣で、自力で EOS 終端）と全角スペース連続（cc100-ja に実在する

repetition penalty が効くタイプ。

loss が 0.07 高い点は recency prior による長距離参照のハンディか揺らぎか、このステップ数
では判別できない（→ 5.5 でマルチヘッド化により解消）。

### 5.5 マルチヘッド化（run `d1024-h8-l16-leveldecay`、8 ヘッド + レベル減衰、5000 ステップ）

1H 減衰 3.69）— 減衰による loss 劣化はヘッド数で回復して余りある。

生成の汎用反復指標（文字 bigram 異なり率。生成末尾 1/4 で低いほど反復。seed 0–2 × 3 プロンプト）:

|---|---|---|---|---|---|

- temperature 0.7 では 8H 版に「位置」9→17→20→22、「語」12→20→26→33 のような

  補正なし版の「サンプリング設定によらず指数的に崩壊する」執着とは質的に異なる
- 結論: レベル減衰で致命的な執着（多重計上の正帰還）は解消、マルチヘッドは loss を改善し
  反復耐性を損なわない。残る語レベル反復は小規模 LM 一般の性質で、repetition penalty や
  temperature で制御する領域

### 6.2 T=1 異常の原因: 同一トークン連続区間での位置縮退（確認済み）

T=1 の配置（桁 0–9、マーカー `9` が 10–20）で答え位置 s=18（桁 7）と s=19（桁 8）を比較:

- 第 1 層: 両者の見る kv 集合は全レベルで同一（レベル 0 = `9`×4、レベル 1 = サブユニット
  0–3、最上位 = サブユニット 0）→ 出力は **厳密に一致**（実測 相対距離 0.00）
- 第 2 層: 唯一の差はレベル 0 窓が {h14,h15,h16,h17} vs {h15,h16,h17,h18} になる点だが、
  h14=h15（レベル 1 位相 j=3）と h16=h17=h18（j=0）の差自体が微小（2e-3）なので、
  混合比 2:2 vs 1:3 の差は **相対距離 1.9e-3** にしかならない（隣の s=20 とは 0.9）
- 結果、`pred[18]==pred[19]` が **99.9%** のサンプルで成立し、位置 7・8 の正答率の和は
  1.118 ≈ 1 + 1/8（片方だけ正解 + 桁が偶然一致する確率）— 完全縮退の予測値と一致

一般化すると: **同一トークンの連続区間では、レベル位相の切り替わりを挟まない位置どうしの
多重スケール窓が一致し、モデルは区間内で「何個目か」を数えられない**（位置符号化ゼロの
構造的帰結）。T≥2 では答え位置が位相の切り替わり（j の変化）をまたぐため衝突しない。
本番 LM の生成で見られた全角スペース連続ループも同じ機構（空白の連続区間内で位置を
失い、いつ止めるか決められない）の可能性がある。

### 6.3 学習可能位相埋め込み（run `logkv-d512-logu-phase`）— Copying 完全解

§6.2 の縮退対策として、絶対位置 s の C 進数展開 s = Σ j_i·C^i の各桁で選ぶ学習可能ベクトル
（レベルごとに C 本）の和を attention 入力（q/k/v 射影の前）に加算する `phase_emb` を追加
（config `phase_emb`、既存チェックポイント互換のためデフォルト False、`--phase-emb`）。
残差ストリームには入れない。有界・周期的で系列長に依存しない。

結果（同条件の Copying、best ckpt 44700）: **T=1〜1,048,576（訓練域の 517 倍）の全ホライズンで
string accuracy 1.000**、T=1 の位置別正答率も全 1.00。詳細は
[instruction-for-claude/copying-task.md](instruction-for-claude/copying-task.md) 末尾。

- 位置 0–9 の位相タグは T によらず固定なので、桁の value が「(桁, 位置タグ)」の束縛表現として
  圧縮を通過し、上位レベル 1 本のベクトルに 10 組が重ね合わせで保存される。答え位置では
  マーカー区間内のカウントが位相で可能になり、位置タグで復号する
- 位相なし版の遠距離 plateau の主因はレベル減衰の log d 逆風ではなく、位置縮退と順序符号の
  欠如だったと結論できる（レベル減衰は 1M トークン先の検索を妨げていない）

### 6.4 位相埋め込み版の Selective Copying — 域内改善・域外崩壊

同条件で Selective に適用（詳細は
[instruction-for-claude/selective-copying-task.md](instruction-for-claude/selective-copying-task.md) 末尾）。
域内は大幅改善（T=64 str 0.04→0.38、T=1 完全回復）だが conv 版には届かず、**T≥2029 で
tok がチャンス水準（0.15–0.24）まで崩壊**（位相なし版は bag 最適 0.41 を維持していた）。

原因: 位相埋め込みは絶対位置の C 進数コードで、訓練で出現しなかった桁値（max_t=2028 では
レベル 5 の {2,3}、レベル 6 以上の非零）のベクトルが未学習のまま。域外では答え位置自身の
高位桁が未学習値になり、位相に依存した検索が壊れる。Copying は桁が位置 0–9 に固定で
低位桁しか使わなかったため無事だった。対策候補: `phase_levels` を訓練で全桁値が出現する
範囲に制限（周期的コードにして外挿を保証）、または訓練時の位相起点ランダムシフト。

### 6.5 位相レベル数の制限（phase_levels ∈ {2, 5}）— 周期的コードで外挿回復

詳細は [instruction-for-claude/selective-copying-task.md](instruction-for-claude/selective-copying-task.md) 末尾。

| Selective T | phase16 | phase5（周期 1024） | phase2（周期 16） |
|---|---|---|---|
| 32（域内）| str 0.48 | **0.61** | 0.31 |
| 2048（域外）| tok 0.27（崩壊）| 0.57 | **0.63** |
| 131072 | 0.15 | 0.32 | **0.54** |

- 全桁値が訓練で出現する周期に制限すると域外崩壊は消える。周期が長いほど域内の順序精度は
  上がるが、域外で折り返しが増えるとタグが衝突する（エイリアシング）ため遠距離で劣化。
  周期 16 は訓練中から常時折り返すため局所順序のみに使われ、遠距離は全構成中最良
  （bag 最適を全域で上回る）
- Copying は phase2 でも全ホライズン 1.000（収束は phase16 より速い）
- 推奨: 外挿・無限生成を重視するなら `phase_levels=2`（周期 16）。ctx 内の順序精度を
  取るなら 5（ただし域外はエイリアシングで劣化）

### 6.7 学習可能減衰係数（`learnable_decay`）

レベル減衰の係数 β（初期値 log C）を層・ヘッドごとの `nn.Parameter` にした（デフォルトは
固定、`--learnable-decay`）。phase2 構成で Copying / Selective を再実験。詳細は各タスクの
doc 末尾。

| | Copying | Selective |
|---|---|---|
| 域内 | 1.000（不変） | T=64 str 0.11→**0.29**、T=1024 0.00→0.04 |
| 域外 | 65k まで 1.000、98k–131k で 0.988–0.996 | 2048 tok 0.63→**0.68**、131k 0.54→0.52（同等） |
| 学習された β | 両層とも log C 近傍（1.2–2.0） | 第1層 ≈ log C、**第2層は 8 頭中 6 頭が負（−1.0〜−1.6）** |

- β は Copying では log C 近傍に留まり（減衰は「不要」にならない）、Selective では第2層が
  **反減衰の長距離検索ヘッド**に分化した。固定 log C は執着対策として安全側だが、検索が
  必要な層には制約だった
- 域内改善と外挿維持を両立する最も均衡の取れた Selective プロファイル（ただし conv 版との
  差は依然大きい）
- **本番 LM 検証**（run `d1024-h8-l16-ph2-ldecay`、§6.6 と同条件 + `--learnable-decay`）:

| | 位相版（固定 log C） | 位相版 + 学習可能減衰 |
|---|---|---|
| EMA loss @5000 | 3.565 | **3.558** |
| temp 0.7: EOS / Q4 異なり率 / 重反復 | 6/9 / 0.60 / 4/9 | **4/9 / 0.35 / 6/9**（悪化） |
| temp 1.0: EOS / Q4 異なり率 / 重反復 | 7/9 / 0.87 / 0/9 | 7/9 / 0.81 / 0/9 |
| 学習された β | — | 全 128 頭が正（0.75–1.85）、**平均 1.11、93% が log C 未満**。負の頭なし |

  - 負の β（Selective で現れた反減衰の検索ヘッド）は LM では生じないが、大半の頭が
    log C より**弱い減衰**を選ぶ。loss はわずかに改善する一方、temp 0.7 の生成で話題語への
    ロックイン（大阪 56→119→120→120、アラブ 1→34→57→54 など四分位で高止まり）が増え、
    重反復 6/9。指数的崩壊（§5.1）ではないが、§5.2 の「減衰が弱いほど多重計上の正帰還が
    強まる」機構どおりの品質劣化
  - LM の尤度目的は（反復の多い web テキストで）弱い減衰を好むが、生成品質とは逆方向。
    loss 差 0.007 に対して反復悪化は大きく、割に合わない
  - 判断材料: (a) LM は固定 log C のまま（現状の安全策）、(b) β の下限を log C にする
    （β = log C + softplus(δ)、減衰は強める方向にのみ学習可能）、(c) 検索が要るタスク
    （Selective 系）では学習可能を使う

### 6.8 標準構成の確定

LM の標準構成は **固定 log C のレベル減衰 + 位相埋め込み（phase_levels=2）+ マルチヘッド
+ gated attention（§6.9）+ self slot（§6.16）** とする
（`--phase-emb --phase-levels 2 --gated-attention --self-slot`、`learnable_decay` は使わない）。

**kv_norm はオプション**（一時は標準に含めたが §6.13 の結果で外した）: LM の loss 改善は僅か
（3.489→3.452）な一方、key ノルム符号化を塞いで完全記憶の限界を 26–52 万トークンまで縮める
（kv_norm なしは 16.8M でも完全）。超長文記憶の価値を優先し、kv_norm は Selective 域内精度が
要る用途向けに残す。学習可能減衰も同様に Selective 系向けオプション。

gated 版（`d1024-h8-l16-ph2-gated/checkpoint-5000`）は predict_stream.py で複数回試行し、
安定した回では **30,000 トークン以上**（訓練 ctx の 15 倍超）の連続生成が確認された。
kv_norm 版（`d1024-h8-l16-ph2-gated-kvnorm/checkpoint-5000`）も約 15,000 トークンの連続生成で
安定を確認。

### 6.10 Compressor プーリングの鋭さの計測（レベル減衰の符号の再検討）

レベル減衰 −i·log C の導出は「プーリングが鋭く value が希釈されない（同一トークンが全レベルに
フル濃度で複製される → 多重計上）」を仮定している。逆に均等プーリングなら value は 1/C^i に
希釈されるので、各トークンに等しい重みを与える補正は **+i·log C**（符号が逆）になる。どちらの
体制かを、学習済みモデルの Compressor attention 重み（チャンク末尾 q によるプーリング重み）で
計測した（均等なら max 0.25 / entropy 1.39、one-hot なら 1.0 / 0）。

| モデル | L0 max / ent / >0.9 | L1 | L2 | L3 |
|---|---|---|---|---|
| 本番 LM（16 層の典型値） | 0.53 / 1.02 / 10% | 0.55 / 0.98 / 12% | 0.51 / 1.06 / 9% | 0.50 / 1.08 / 7% |
| Selective（gated, 2 層） | 0.74 / 0.53 / 52%、0.51 / 1.11 / 5% | 0.73 / 0.57 / 47%、0.67 / 0.76 / 33% | 0.65 / 0.67 / 51%、0.63 / 0.80 / 31% | 0.73 / 0.50 / 60%、0.75 / 0.57 / 45% |
| Copying（gated, 2 層） | **0.99 / 0.02 / 100%** | 0.91 / 0.24 / 64% | 0.29 / 1.30 / 5% | 0.40–0.56 |

- **どのモデルも均等（0.25）ではない**が、LM は one-hot でもなく **中間体制（最大重み ≈ 0.5、
  上位 1–2 トークンの混合）**。層 0–1 は 0.44 とやや均等寄り、中間層以降 0.5–0.6
- Copying はレベル 0–1 で完全な選択（blank を捨てて桁を残す、max 0.99）、レベル 2 以降は
  複数桁を重ね合わせで保持するため混合（0.3–0.5）
- Selective は中間〜鋭い（0.65–0.75）
- 含意: 顕著トークンの value はレベルごとに ρ ≈ 0.5（LM）の因子で減衰しながら上位へ複製される。
  多重計上を「1 回分」に潰す等比比は e^(−β)·ρ なので、中立点は β = −log ρ ≈ log 2 = 0.69、
  固定 log C = 1.39 はそれより強い recency（LM が学習で選んだ β ≈ 1.1 は両者の間）。
  均等仮定の +log C は e^(β)·ρ = 2 > 1 で古い内容を増幅する方向になり、LM では執着を招く
- 符号の正しさはプーリングの鋭さ ρ に依存し、ρ は学習・内容依存。設計上の選択肢は
  (i) Compressor で pooled value を再正規化（例: Σα_j v_j / max_j α_j で顕著トークンの振幅を保存）
  して ρ=1 の体制に構造的に揃え、−log C が常に整合する形にする、(ii) β を ρ に合わせて設定
  （−log(C·ρ)）、(iii) 現状維持

### 6.11 kv_norm（k/v の全レベル同一スケール化）

§6.10 の議論から、pooled value の max 正規化（混合体制で振幅が増大する）ではなく、**k/v に
head_dim 単位の RMSNorm を射影直後（レベル 0）と各圧縮後に同じモジュールで適用**する `kv_norm`
を実装。全レベルのスロットが RMS 1 × ゲインになり、レベル依存のスケールは明示的な −i·β のみに
なる（混合による k/v ノルム縮小が作っていた鋭さ依存の暗黙 recency を除去）。gated 版 +
`--kv-norm` で Copying / Selective を再実験。詳細は各タスクの doc 末尾。

| | Copying | Selective |
|---|---|---|
| 域内 | 1.000（不変、EMA loss 7e-10 で最小） | T=32 str 0.57→**0.88**、T=64 0.30→**0.78**、T=256 0.15→**0.56**（conv+sink: 0.88 / 0.86 / 0.69） |
| 域外 | 131k まで 1.000（98k のみ 0.996） | 2048–4096 は conv+sink と同等（tok 0.82 / 0.77）、**≥16k は gated 版より劣化が速い**（131k 0.36 vs 0.61） |

- Selective 域内で初めて conv+sink 版にほぼ並んだ（位置補助機構なしで）。学習も明確に良い
  （訓練 str 0.84 vs 0.67、EMA loss 0.0032 vs 0.010）
- 超遠距離は gated 版に劣る: 正規化で暗黙 recency が消えた分、遠距離では同一スケールの多数
  スロットが競合する（域内精度と超遠距離のトレードオフ）。本番 LM（ctx 2048、生成は数万
  トークン）ではどちらが効くか要検証
- **本番 LM 検証**（run `d1024-h8-l16-ph2-gated-kvnorm`、§6.9 と同条件 + `--kv-norm`）:

| | 位相版 | gated（標準構成） | **gated + kv_norm** |
|---|---|---|---|
| EMA loss @5000 | 3.565 | 3.489 | **3.452** |
| temp 0.7: EOS / Q4 異なり率 / 重反復 | 6/9 / 0.60 / 4/9 | 3/9 / 0.51 / 5/9 | 5/9 / 0.56 / 4/9 |
| temp 1.0: EOS / Q4 異なり率 / 重反復 | 7/9 / 0.87 / 0/9 | 7/9 / 0.75 / 0/9 | 7/9 / **0.86** / 0/9 |
| 最長同一文字連続 | 3 | 2 | 2 |

  - **loss は −0.037 でさらに最良**（位相版から累計 −0.11）。序盤の立ち上がりも速い
    （step 100 で 10.03 vs gated 10.48: 正規化された k/v で logit スケールが最初から整う）
  - 生成の反復指標は gated 版より改善し位相版と同等（temp 0.7 重反復 4/9、temp 1.0 で
    Q4 異なり率 0.86）。最頻語の四分位推移は緩やかな高止まり（都市 38→45→49→52）はあるが
    指数増殖はなく、暗黙 recency の除去による執着悪化は見られない
  - Selective で見えた「超遠距離の劣化」は ctx 2048 の LM 訓練・数千トークンの生成では
    顕在化せず、域内精度側の利得が出た形
  - 判断: loss・生成品質とも改善で執着再発なし。**標準構成への追加は妥当**

### 6.12 レベル増幅（`level_amplify`、符号反転 +i·log C）の検証 — 減衰を維持

ユーザーの符号反転実験（predict_stream で 15k トークン安定生成、run `amplify-past-test`）を
受け、`level_amplify` オプションとして正式化し標準構成の符号だけ反転して全面比較した。

| | 標準（減衰 −i·log C） | 増幅（+i·log C） |
|---|---|---|
| Copying | 全域 1.000 | 2048 まで 1.000、131k で **0.926**（16k から崩れ始め） |
| Selective T≤64 | str 0.78–0.98 | **str 0.87–1.00（T=32 0.96 で全構成最良）** |
| Selective T≥128 | str 0.62 / 0.56 / 0.26（128/256/1024） | 0.49 / 0.29 / 0.15、131k tok **0.17**（bag 最適未満） |
| LM eval loss（wiki_ja 同一 16 サンプル） | **3.261** | 3.298 |
| LM temp 0.7: EOS / Q4 / 重反復 | 5/9 / 0.56 / 4/9 | **1/9 / 0.30 / 8/9**（神戸 77→86→86→86 等の高止まり） |
| LM temp 1.0 | 7/9 / 0.86 / 0/9 | 7/9 / 0.76 / 0/9 |

- 増幅は §6.10 の希釈補正として**ごく近距離（T≤64）の要約読み出しには全構成最良**に効くが、
  +i·log C の事前重みが遠距離で内容マッチを圧倒し（レベル 8 で +11 ロジット）、対数長期記憶
  という本アーキテクチャの利点を失う。LM でも loss・temp 0.7 の反復（文書を終えられず話題語が
  高止まり）とも悪化
- **結論: 標準構成は減衰（−i·log C）を維持**。増幅は近距離読み出し特化のオプションとして残す

### 6.13 記憶距離の限界 — 減衰は限界を作らない

Copying モデルで完全記憶の限界距離を探索（詳細は
[instruction-for-claude/copying-task.md](instruction-for-claude/copying-task.md) 末尾）。

- レベル減衰は指数的（C^−i）でも距離→レベルが対数なので、合成の事前重みは **∝ 1/d（多項式）**。
  必要な内容マッチのマージンは Δ ≈ ln d + ln(スロット数) と対数でしか増えない
- **位相のみ構成は 16.8M トークン（訓練の 8273 倍、圧縮 12 段）でも token/string 1.000** —
  限界は測定範囲外
- **標準構成（gated+kvnorm）の完全記憶は 262k〜524k で崩れる**（実効マージン ≈ 13 nat）。
  kv_norm が key ノルムを固定し「重要トークンの key を長くする」符号化を塞ぐため。
  Selective の超遠距離劣化（§6.11）と同根。崖の先も tok 0.6–0.9 の緩やかな劣化で崩壊はしない
- 含意: kv_norm は「域内・近距離の精度」（§6.11）と「10⁵ 超の超遠距離マージン」のトレードオフ。
  LM 用途（ctx 2048、生成数万トークン）では kv_norm の利得側が勝つが、超長文記憶を狙う
  用途では kv_norm を外す（または key 側のみ外す）選択肢がある

### 6.14 v_norm 単独の分解検証 — 両取り不成立、norm 系は標準に入れない

`v_norm_only`（v のみ RMSNorm、k は非正規化）で kv_norm の効果を分解（詳細は各タスク doc 末尾）。

| | Copying 限界 | Selective 域内 (T=64 str) | Selective 遠距離 (131k tok) |
|---|---|---|---|
| 標準（norm なし） | ≥16.8M | 0.30 | **0.61** |
| kv_norm | 262k–524k | **0.78** | 0.36 |
| v_norm のみ | **≥2M（プローブ上限）** | 0.45 | 0.50 |

- kv_norm の **域内改善も遠距離喪失もどちらも key 正規化由来**。v_norm 単独は利得が小さく、
  Selective では近距離（T≤16）を悪化させ遠距離も削る — 「情報の薄い混合が小ノルムとして
  伝わる」value の振幅チャンネルを毎段リセットする害（ユーザーの直観どおり）
- Copying では v_norm は 2M まで無害（記憶 value が鋭い重ね合わせで再正規化に頑健なため）
- **結論: norm 系は標準構成に入れない**（§6.8 の標準構成を維持）。kv_norm は Selective
  域内特化のオプションとしてのみ残す

### 6.15 softplus 減衰（β = log C + softplus(δ)、強化方向のみ学習）

大規模 LM（d1024/32 層、29k 步）の生成で「コンテキスト序盤の執着」（最頻語が D1→D4 で
12→20 と増殖し D5–6 で脱出、`text/ai-20260903-29000step.txt`）が観測されたことへの対策候補。
序盤はレベル数が少なく序盤内容への減衰が浅いため、β を強める方向の自由度が最も直接に効く
はずという設計。§6.7 の「β < log C で反復悪化」を下限制約として構造化（δ init −4 ≈ 床）。

タスク検証（標準構成 + `--softplus-decay`、d512/2 層）:

- **Copying**: 通常評価 1.000（〜65k）。最終 ckpt は記憶限界テストでも **262k〜16.8M
  すべて 1.000** — 制約は記憶限界を損なわない。best ckpt(25200) では 262k 以降崩れており、
  best 選定（訓練精度基準）が長距離マージンの成熟を反映しない教訓（限界測定は最終 ckpt で）
- **Selective**: 全域で gated 標準と同等
- 学習された β は両タスクともほぼ床（1.39–1.42）: タスクの尤度は減衰強化を要求しない。
  制約が「必要な場面でだけ発動する安全な自由度」であることの確認
- 副産物: **gated 標準（kvnorm なし）の記憶限界を初計測 — 16.8M（8273 倍）まで完全**。
  §6.13 の 262k 崩壊は kvnorm 起因と確定
- **本番 LM 検証**（run `d1024-h8-l16-ph2-gated-spd`、§6.9 と同条件 + `--softplus-decay`）:
  **β は 128 ヘッド全てが床（1.40–1.42）に張り付き、1.5 超は 0 頭**。EMA loss 3.489（gated
  標準と同値）、生成指標も同等（temp 0.7: EOS 4/9 / Q4 0.51 / 重反復 4/9、temp 1.0: 0/9）。
  §6.7（自由な β は log C を下回りたがる）と合わせて、**尤度勾配は常に減衰を弱める向き**で、
  序盤執着の抑制方向に β を押し上げることはないと結論。softplus 制約は LM で無害だが、
  学習に任せる設計では序盤執着に効かない
- 序盤執着への次の手の候補: (a) 訓練延長（29k 步時点で D5–6 で脱出できており、序盤の校正が
  訓練とともに改善する可能性）、(b) 生成側の対策 — chat_server の減衰付き repetition penalty
  を predict 系へ移植して序盤の増殖ループを直接抑える、(c) 序盤（スロット総数が少なく
  各スロットの事前シェア 1/(C·levels) が大きい期間)だけに効く明示的な補正の設計

### 6.16 self_slot（クエリ自身の k/v を1スロット追加 = 通常の causal mask と同じ意味論）

LogKV のクエリは再帰構造の都合で「自分を**除いた**過去」のスロットしか見えない。表現能力の
面では残差経路が自トークンを運ぶので差はないが、**softmax の中に「何も聞かない／自分を聞く」
逃げ場が無い**点が通常の causal attention と本質的に違う（総和 1 の mass が必ず過去のどれかに
注入される = attention sink 問題。gated attention の大きな利得（§6.9）はこの逃げ場を softmax の
外で与えたものと解釈できる）。現在トークンの k/v をレベルバイアス 0 の追加スロットとして
online softmax にマージする `self_slot`（無パラメータ、位置 0 も自分の value を出力）を実装。

**本番 LM 検証**（run `d1024-h8-l16-ph2-gated-self`、§6.9 と同条件 + `--self-slot`）:

| | gated 標準 | ＋ self_slot |
|---|---|---|
| EMA loss @5000 | 3.489 | 3.497 |
| temp 0.7: EOS / Q4 異なり率 / 重反復（1024 tok） | 3/9 / 0.51 / 5/9 | 5/9 / 0.59 / 4/9 |
| temp 1.0: 同上 | 7/9 / 0.75 / 0/9 | **8/9 / 0.79** / 0/9 |
| 4096 tok × 3（temp 0.7）: 後半（D6–D10）で異なり率 <0.15 の崩壊 | **3/3** | **1/3** |
| 4096 tok: D1 最頻語の単調増殖（序盤執着の署名） | 1/3（宇宙 14→26） | 0/3 |

- loss は同等（gate が既に逃げ場を担っているため、予想どおり loss 寄与は小さい）
- 生成は一貫して僅かに良い方向: 1024 の反復指標、4096 の崩壊率（3/3 → 1/3）、序盤執着の
  署名（1/3 → 0/3）。ただし n=3 なので効果量の確度は低い
- 残る崩壊は温度 0.7 の mode-seeking によるリスト反復（心臓病・脳卒中、組織名、日付）で、
  逃げ場の有無とは別の機構
- **勾配の安定化**: warmup 後の grad_norm は平均 1.14→0.74、標準偏差 0.40→0.19、最大
  4.39→3.13（最終 1000 步: 0.89→0.66）。softmax が過去スロットに mass を強制注入しなくて
  済む分、attention 経路の勾配が穏やかになる
- **標準構成に採用**（2026-09-04）: 無パラメータ・loss 中立・意味論が通常 causal と一致・
  生成は悪化せず・勾配が安定。序盤執着への効果は大規模（32 層・29k 步）構成での再確認が必要

### 6.17 重複なしの階層参照（2026-09-06）

[改良図](../logkv-refine.drawio.png)に合わせ、各レベルで前ブロックから補っていた
`c >= j` のスロットを削除した。圧縮処理そのものは維持し、完成したチャンクは上位の要約
だけで参照する。例えば位置4でトークン0,1,2,3と要約0〜3を同時に見る重複がなくなる。

- レベル i の参照区間は `[u*C^(i+1), u*C^(i+1) + j*C^i)`。直下のレベルの参照区間は
  この右端から始まるため、全階層を合わせると [0,s) を重複・欠落なく覆う
- 有効スロット総数は位置 s の C進数の桁和 `Σ_i j_i`（self slotは別）。最大は各レベル C−1個、
  `O(C·log_C L)`。softmaxの候補テンソルも各レベル C→C−1に縮小
- hiddenから `prev_k/prev_v` を削除し、各レベルに `cur_q/cur_k/cur_v` のみ保持。
  未完成部分をcloneすることで、推論時の実ストレージも対数サイズに抑える
- パラメータ形状・Configのフラグは変更なし。旧チェックポイントの重みは読み込めるが、
  attentionの意味論が変わるため従来の出力は再現しない。旧形式の実行中hiddenは互換性がなく、
  推論は `hidden=None` から開始する
- レベル減衰、位相、ゲート、self slot、norm等の設定は維持。重複由来の多重計上は構造的に
  消えるため、減衰の必要性・生成品質・長距離記憶は新構造で再評価する
- 検証: C=2/3/4で一括・境界をまたぐ分割処理の参照範囲を追跡し、過去の各位置が1回ずつ
  含まれることを確認。独立参照とのfp64一致、self slotの有無、未来入力への非依存、
  分割逆伝播の勾配一致、キャッシュの実ストレージ量、LMの保存・読込・生成をテスト

Copying / Selective Copyingの再学習・評価は§6.18に記録。新構造のLM生成品質は未評価。
§4–6.16の結果は重複あり構造のベースラインとして残す。
