2026-09-10、自己スロット除去の学習・評価・診断が完了した。
準備commitは`7be979f`、GPU 0の1台で10:30:06〜14:35:35 JST、約4時間6分。

自己スロットありの既存結果を対照に、自己スロットなしを初期状態から1本学習する。

## 診断：残った誤りの特徴

**1. 距離だけでは説明できない、内容・出力桁に依存した誤りがある。**
自己ありbestは固定した16記憶列について、T16・8192・32768・65536・131072のすべてで、
同じ1例の8桁目を「1→3」と誤った。各Tで15/16例完全一致であり、短距離ですでに起きている誤りが長距離でも残った。
これは少なくともこの例では、距離が増えるにつれて単調に記憶を失うという説明に合わない。

T131072の既存256例を再評価し、best/finalとも247例完全一致・2551桁正答を再現した。
bestの9誤答は7桁目1例・8桁目5例・9桁目3例、finalは3桁目1例・7桁目8例。
それぞれ1例につき1桁の誤りで、best/finalで誤った例の重複は0だった。

**2. T49152付近では、一桁先の記憶値を出力する現象が確認できた。**
同じ16記憶列を使った自己ありbestの結果は、T49151で15/16、T49152で3/16、T49153で5/16。
T49152で9桁目を誤った13例は、すべて10桁目の記憶値を出力していた。
T49153で8桁目を誤った11例は、すべて9桁目の記憶値を出力していた。
どちらも0始まりの絶対位置49170に対応する。回答の先頭は位置T+10なので、
Tを1増やすと同じ絶対位置が回答の9桁目から8桁目へ移る。
fp32でもT49152の9桁目に残る11誤答はすべて10桁目の値だった。

自己なしbestはこの近傍で0/16→10/16→16/16となり、低下箇所が変わっている。
したがってT49152という1点の改善だけでは解決と判断できない。
この観察は特定の位置・階層構造に依存する桁選択の誤りを疑う材料だが、
相対位相、圧縮表現、層間の情報伝達のどれが原因かを単独で切り分けたものではない。

**3. bf16の丸めは一部に関係するが、主因をそれだけに帰すことはできない。**
自己ありbestのT131072でbf16が誤った9例をfp32で評価すると、3例が完全一致へ回復し6例は残った。
回復したのは9桁目の3例。finalの9誤答はfp32でも全例残った。
bestのbf16誤答で正解logitと最大競合logitの差は−3.03125〜−0.28125で、すべてが同点付近というわけではない。
finalにはbf16で同点だった1例もあるが、fp32でも誤答した。
これは誤答だけを選別した再評価であり、256例全体のfp32精度を測った結果ではない。
fp32化で重みと計算の両方が変わるため、丸めの発生箇所も未特定。

**4. 回答時の自己注意量増大だけでは、元モデルの誤答を説明できない。**
自己ありのT131072誤答位置では、第2層の自己スロット注意量（head平均）はbestで最大約2.85×10⁻¹⁶、
finalで最大約2.77×10⁻²²とほぼ0だった。元の10桁区間に重なるスロットへの注意量は0.5または0.625あり、
同じ出力桁の正答例でも同じ値だった。第1層の自己注意量も、同じ出力桁の正答例・誤答例でほぼ同じだった。
回答時の第2層で自己スロットが記憶への注意を奪っているという単純な説明は、この測定では支持されない。
ただし、記憶区間への注意量は保持された情報の量ではなく、読み込んだ値やその後の変換が正しいことも保証しない。
計測は回答位置のみなので、それ以前の自己スロットの作用や第1層を介した影響は除外できない。

## 仮説と比較範囲

自己スロットのlogit `qᵀk / sqrt(d_head)`はRoPEの相対距離0に対応し、位置の扱いに不整合はない。
今回調べるのは、減衰のない自己スロットが粗い階層の記憶とsoftmax内で競合し、読み出しを妨げる可能性。
自己スロットの除去は過去への注意を強める一方、不要な過去を参照しないための選択肢も失う。
改善・悪化のどちらもあり得る。除去して再学習する比較だけで、競合が原因と断定することはできない。

| 条件 | 対照 | 今回 |
|---|---|---|
| phase embedding | false | false |
| retrieval RoPE | true | true |
| compressor RoPE | false | false |
| self slot | true | false |
| 固定レベル減衰 | −i log C | −i log C |
| その他 | gated attention、C4、d512、8 heads、2層、d_ff1024 | 同一 |
| 学習 | M10固定、prefixなし、50k steps、batch64、T loguniform[1,2028]、全位置CE | 同一 |
| seed | 初期化0、学習データ1、標準評価12345 | 同一 |
| 精度 | fp32学習重み＋bf16 autocast、標準評価bf16重み＋autocast | 同一 |
| best選択 | 訓練100 steps区間のstring/token/−EMA loss | 同一 |

対照は[前回の読み出しRoPEのみのCopying](logkv-rope-only.md)のbest/final。
保存済みconfigと凍結コードから再構成した初期重みは自己スロットあり・なしで完全一致し、初期化後の乱数状態も一致する。
自己スロットに固有の学習パラメータはなく、両方5,786,112 parameters。
元実験のstep 0の重みは保存されていないため、比較は初期化の再構成による確認である。
同じタスク・データgenerator・seed・学習コマンドを使用するが、浮動小数点演算の再現性を全環境で保証するものではない。

## 評価と診断

1. **標準評価**：自己スロットなしのbest/finalをT131072まで全41点×256例で評価する。
   凍結された標準評価器の計算をそのまま使い、各例の記憶列・予測した10桁・正解logitと最大競合logitの差も保存する。
2. **記憶列を固定した比較**：別seed4321の16列を固定し、両構成・両checkpointで
   T=3,16,8192,32768,49151,49152,49153,65536,131072をbf16評価する。
   T49152前後も同じ記憶列で比較する。これは境界の全面走査ではない。
3. **注意量**：回答10位置について、各層・各headの自己スロット、各階層、元の10桁区間に重なるスロットへの注意量を保存する。
   後者は区間の重なりに基づく量であり、実際に残存する記憶情報の量ではない。出力logitと全headの注意量はNPZに保存する。
4. **精度比較**：同じ16列のT49152・131072を両構成・両checkpointでIEEE fp32（TF32なし）評価する。
   bf16との違いには重みの丸めと途中計算の丸めの両方が含まれ、どちらか一方の切り分けではない。
5. **既存の9誤答の再現**：対照best/finalのT131072・256例を元のseed・batchサイズで再評価し、
   247列完全一致・2551桁正答の再現を必須検証にする。各checkpointで誤った9列だけをfp32でも評価する。
   これはbf16誤答で選別した例の診断であり、無作為標本に対する精度ではない。

既存モデルの推論時だけ自己スロットを外す実験ではなく、学習時から除去した比較を行う。
各構成1学習seed、診断は基本16列。注意量との相関だけで誤答の原因を断定しない。
CopyingとSelectiveは別タスクであり、この実験ではSelectiveを追加学習しない。

モデル本体は変更していない。
