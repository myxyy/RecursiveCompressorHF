## 桁の識別に関する解析

桁番号はすべて**1始まり**。出力のargmaxと正解列を比較した観察で、hidden表現やlogitベクトルの厳密な同一性を測定したものではない。
回答時の入力はマーカー9の列で、予測した桁を次の入力へ戻さない位置対応の評価形式である。

### 短距離で解ける桁は増えた

Copying bestのT=16では第7桁の誤答が125→1/256、T=64では第8・9桁が104→0、91→0/256に減った。
T=64で2層の誤答から完全一致へ変わった例は210、逆に完全一致から誤答になった例は4。
単なる評価標本の違いではなく、同じ記憶列に対する改善である。

ただし短距離も全解ではない。T=48は3層bestで15/256、finalでは0/256で、
T=14のbestも123/256に下がる。3層bestで256/256だったのは標準41点中T=11のみ。
「T=192以下なら完全一致」とは言えない。

過去の重複あり構造の診断で問題だったT=1の第8・9桁について、今回の2層bestは
誤答が1/256・0/256、全列完全一致253/256だった。正解の第8・9桁が異なる221例のうち、
両出力が同じになったのは1例。旧構造の特定位置の識別困難性を現在のmainにそのまま適用できない。

### 長距離では別の位置の取り違えが現れる

3層bestはT=192で234/256完全一致だが、次の評価点T=256では0/256になる。
T=256の**第3桁は256例すべてで正解の第2桁を出力**した。第2・3桁が偶然同じ30例だけ正解で、
異なる226例はすべて誤答。これは独立なランダム誤答よりも、特定の桁を繰り返す出力になっている。
T=131072でも第3桁が正解の第2桁と一致するのは255/256例。最初の2桁は両Tで256/256正解なので、
少なくとも記憶内容が一様に消失したわけではない。

一方、同じ3層構造のfinalではT=256の第3桁が249/256正解する。したがって、
**このT・この桁の衝突は3層アーキテクチャが必ず強制する識別不能性ではない**。
ただしfinalも第9・10桁で122・218/256誤答し、完全一致は9/256にとどまる。
さらにfinalのT=1024では第4桁が正解の第3桁と255/256例一致し、別の取り違えが現れる。
全10桁の安定した読み出しを同時に学習できたことにはならない。

![全評価点の桁別誤答率](experiments/logkv-no-position-3layer-20260913/analysis/digit_errors.png)

bestの低下は評価点192→256、finalの桁精度の大きな低下は768→1024に見られる。
256=4^4、1024=4^5なので圧縮階層との関係は候補だが、
この疎な評価点だけで低下開始位置や因果関係を確定できない。T=48の回答位置58～67が
64境界をまたぐことも同様に手掛かりであり、境界が原因と検証済みではない。
これらは訓練範囲T≤2028の中で既に起きているため、単なる訓練長を超えた外挿失敗としては説明できない。

### Selectiveは広く改善したが、中盤の桁が残る

Selectiveの桁精度はbest/finalそれぞれ全41点で3層が上回った。完全一致数はbestで39点改善・2点同数、
finalで29点改善・12点同数、悪化した評価点はない。T=131072のbest桁精度は21.72%→62.38%で、
先頭・末尾も含め多くの桁が改善する。第1桁の誤答は161→0、第2桁191→4、第10桁213→33/256。

ただし同Tの3層bestの第4～9桁は103～171/256誤答しており、完全一致は1/256。
T=64でも第6～8桁が148・126・155/256誤答し、完全一致は11/256（4.30%）にとどまる。
深くすると部分的な選別・保持・読み出しが改善するという結果だが、そのどの処理が改善したかは
今回の出力解析からは分離できない。

## 学習と解釈の限界

最後5,000 stepsの訓練区間平均ではCopyingのstring accuracyは33.91%→46.09%に上がる一方、
token accuracyは86.24%→84.04%に下がる。Selectiveはstring 12.20%→23.63%、token 66.93%→81.85%。
Copyingでは解ける例が増えると同時に、解けない例で多くの桁を失う傾向と整合する。
これらは訓練データ上の区間平均で、固定Tの評価や検証集合のスコアではない。

3層Copyingは訓練途中にも大きな変動があり、33,001～34,000 stepsのstring accuracy平均55.59%から、
35,001～36,000 stepsには5.88%へ低下した（token accuracyも90.60%→51.29%）。
41,001～42,000 stepsにはstring 41.15%へ回復している。
最終時点まで単調に改善した実験ではなく、checkpoint依存の誤答パターンと合わせて、
最適化の安定性も検討対象になる。急落を起こした原因自体は今回の集計からは確定できない。

![学習区間の完全一致率](experiments/logkv-no-position-3layer-20260913/analysis/training.png)

現行訓練はTをloguniformで選び、全位置CEを平均する。回答10桁の損失比重は10/(T+20)で、
同じ桁あたりCEならT=16の27.8%に対しT=1024では約0.96%、T=2028では約0.49%となる。
長いTの回答を正す勾配が小さくなりやすい設定で、短距離を解くことと長距離まで全桁を
安定させることが一致しない一因の候補になる。今回この訓練目的を変えた比較はしておらず、原因の確定ではない。

今回の結論は「3層化は役に立つ局面があるが、位置埋め込みなしで長距離完全一致を得る十分条件にはならなかった」。
特定の出力衝突はcheckpoint間で解消できており、原理的に不可能と結論する根拠にもならない。
学習seedは1個、パラメータ数も約50%増えるため、深さと容量の効果は分離していない。
次に原因を絞るなら、新しい大規模学習よりも既存best/finalでT=192～280、960～1040付近の
細かな評価と層別表現・読み出しlogitの比較が候補になる。これは提案のみで、未実施。

## 比較条件

ここでの層数は積層する`LogKVBlock`の数（`num_layers`）を指す。
各Block内部のKV圧縮は従来どおり再帰的で、圧縮階層の数を3に制限する変更ではない。
凍結ソースは2層実験と共通のmain `0932d8c`で、全27ファイルが`3b0ce51`と一致する。
mainのモデル・通常訓練コードは変更しない。

| 項目 | 2層対照 | 今回の3層 |
|---|---|---|
| num_layers | 2 | 3 |
| パラメータ数 | 5,786,112 | 8,673,792（+2,887,680） |
| GPU | 0=Copying、1=Selective | 2=Copying、3=Selective |
| C / d / heads / d_ff | 4 / 512 / 8 / 1024 | 同左 |
| 位相埋め込み / 追加位置表現 | 無効 / なし | 同左 |
| gate / self slot / 固定−i log C | 有効 | 同左 |
| KV/V norm・level amplification | 無効 | 同左 |
| 記憶長・学習 | 固定10桁、各50k steps、batch64、grad accumulation1 | 同左 |
| T分布・損失 | loguniform[1,2028]、全位置CE | 同左 |
| 最適化 | AdamW、lr3e−4、warmup1000、weight decay0、clip1 | 同左 |
| seed | 初期化0、訓練データ1、評価12345 | 同左 |
| 精度 | fp32重み＋bf16 autocast学習、bf16重み＋autocast評価 | 同左 |
| 評価 | best/final、T131072まで41点、各256例 | 同左 |

`phase_levels=2`は無効な位相埋め込みの設定値として残るだけで、埋め込みは生成しない。
bestは訓練100 steps区間のstring/token/−EMA lossの辞書順で選ぶ。
タスクごとに独立したモデルを初期状態から学習する。

3層モデルをseed0で生成後、embedding・最初の2層・最終norm/headの初期重みを
2層対照の保存済み**未学習**重みと全テンソル一致させる。追加した第3層の重みだけを
3層モデルの新規初期化から残す。この3層初期重みを両タスクで共用する。
学習済み重みの転移は行わない。訓練データは専用generatorを使い、各タスクの
2層・3層でseed・batch・乱数消費手順を揃える。異なるタスク同士のT系列は同一ではない。
