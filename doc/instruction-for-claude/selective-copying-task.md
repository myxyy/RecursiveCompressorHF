
## やること
[Mambaの論文](https://arxiv.org/abs/2312.00752)のFigure. 2にあるタスク
Copyingタスクの実験結果を踏まえてSelective Copyingタスクをやる

## タスク概要
記憶する文字が散らばる以外はCopyingと同じにする

* 語彙は0~9のdigit（語彙数10）
* 入力長はTをパラメータとしてT+20
  - 最初のT+9文字は0で埋め、そのうち10文字を1~8のランダムな文字にする
  - 末尾11文字は9で埋める
  - ターゲットは先頭T+10文字を0埋め、末尾10文字を入力の先頭T+9文字に出現した1~8を出現順に並べる

## モデル、学習、検証
Copyingで使用したものと同じにする

## 本実験
d512 / k=4 / T~logU[1,2028] / 50k step (Copyingのd512-logu-noalibiと同一設定)で

## 本実験の結果 (2026-08-17, best ckpt step 48200)

| T | Copying (同一設定) | Selective |
|---|---|---|
| ≤16 | str 1.00 | str 0.74-0.91 |
| 32-128 | str 0.99-1.00 | str 0.39-0.55 |
| 512 | str 1.00 | str 0.16 / tok 0.80 |
| 2048 (訓練上限) | str 1.00 | str 0.02 / tok 0.65 |
| 8192 | str 0.94 | tok 0.49 |
| 131072 | tok 0.89 (k=8) / 0.20 (k=4) | tok 0.17 (≈chance 0.125) |

観察:
* **SelectiveはCopyingより桁違いに難しい**: 同一アーキ・同一設定で、訓練域内ですら
  Tとともに単調減衰(Copyingは域内ほぼ完璧)。Mambaの主張(content-aware selectionが
  必要なタスク)と整合
* ただし崖ではなく**滑らかな減衰**で、T=2048でもtok 0.65とチャンス(0.125)を大きく
  上回る — 選択は「できるが距離とともに解像度が落ちる」形
* 機構的解釈: 大Tでは大半のチャンクがデータ0-1個のblankチャンクになり、
  (1)圧縮時にデータ桁を確実に拾う選択、(2)大量のblankチャンク圧縮の中から
  データ持ち圧縮を階層越しに識別し続ける選択、の両方が距離に比例して難化する
* 訓練は50kステップ時点でまだ改善傾向(best=48200step, 訓練分布上str 0.63)。
  ステップ延長で域内性能はまだ伸びる余地あり

次の一手候補: 訓練延長 / retrieve_size増(k=8はCopyingで遠距離に強かった) /
compress_size増(選択の容量、ただしクエリ縮退の解消が前提) / 訓練T分布の調整

  伸ばし、選択的コピーでは短距離以外で有害。k=4がバランス点

## 案E: compressor内容依存valueゲートの結果 (2026-08-18)

実装: 圧縮attentionのvalueを `v_j ← sigmoid(W_g x_j) ⊙ x_j` で内容依存ゲート
(key無傷、開放初期化+4、HF post_init対策込み)。d128スモークでは改善
(str 0.09→0.15、copying回帰なし)だったが、**d512本実験では域内が大幅悪化**:

| T | no-gate 50k | vgate 50k |
|---|---|---|
| 8 | tok 0.995 / str 0.945 | tok 0.951 / str 0.598 |
| 64 | 0.897 / 0.426 | 0.804 / 0.125 |
| 512 | 0.804 / 0.156 | 0.625 / 0.000 |
| 2048 | 0.653 / 0.020 | 0.471 / 0.004 |
| 16384 | 0.402 / 0 | 0.366 / 0 |
| 32768 | 0.281 / 0 | **0.319** / 0 |
| 131072 | 0.170 / 0 | **0.220** / 0 |

ゲート値の診断(学習後、レベル0):
* blank: **0.24** / data: **0.52** / marker: 0.71

→ **選択の方向は正しく学習された**(blankをdataの半分以下に抑制、域外遠距離tokの
改善に寄与)が、**dataトークンの透過率も0.52に低下**して情報が半減し、域内精度を
損なった。sigmoid乗算ゲートは「相対選択」と「絶対減衰」を分離できないという
構造問題(copyingで特定したゲート減衰問題が、今回は学習の結果として再発)。

修正候補:
* **ゲートをattention logit加算に変換** `logit_j += log g_j` 相当: softmax正規化で
  相対選択のみが残り、valueの振幅は無傷。数学的にこの診断へ直接対応。
  ただし全blankチャンクの圧縮出力自体を小さくする効果(伝搬ノイズ低減)は失われる
* ゲートの正規化(チャンク内相対化) — 同様の狙い
* 撤退して案C'(decompressor null slot)へ
→ logit加算も「kvが全てblank」では相対選択に帰着して無力、との判断で
  **案Eをrevertし案C'(attention sink)へ転進**(compressor/decompressor双方のkvに追加)

## 案C': attention sink (compressor+decompressor) の結果 (2026-08-18)

実装: 学習可能なsinkベクトル各1本をcompressor kv(チャンクトークン列)と
decompressor kv(検索窓)の先頭に連結。softmaxは必ず合計1を配るため、全kvが
無情報(全blankチャンク/全blank窓)のクエリは混合読み出しを強制されていた —
sinkが「学習された定数を読む」逃げ場になる。normed kv空間にrandn初期化
(initial_contextと同流儀)。

| T | no-gate 50k | no-gate 150k | sink 50k |
|---|---|---|---|
| 8 | 0.995 / 0.945 | 0.992 / 0.949 | 0.994 / **0.949** |
| 64 | 0.897 / 0.426 | 0.944 / 0.645 | 0.925 / **0.523** |
| 256 | 0.853 / 0.266 | 0.883 / 0.391 | 0.881 / **0.320** |
| 512 | 0.804 / 0.156 | 0.842 / 0.250 | 0.830 / **0.230** |
| 2048 | 0.653 / 0.020 | 0.620 / 0.016 | **0.665 / 0.031** |
| 4096 | 0.561 / 0 | 0.472 / 0 | **0.609** / 0 |
| 8192 | 0.489 / 0 | 0.329 / 0 | **0.509** / 0.004 |
| 32768 | **0.281** / 0 | 0.155 / 0 | 0.247 / 0 |

* **vgateと違い域内を犠牲にせず、ほぼ全域で純増**: 同50k比較で中距離(T=64-512)の
  str +0.07〜0.10、T=2048-16384のtokも改善。T≥32kのみ微減(誤差レベル)
* 50k sinkはT≥512で150k no-gateと同等以上 — 訓練効率としても優位
* d128スモークでは初期3000stepの立ち上がりが遅い(attentionがsinkへ流れる過渡期)
  が8000stepで追いつく。d512では悪影響は観測されず
* copying T=1回帰なし、全85テストパス(数値等価性維持)

結論: **sink採用**。ユーザーの判断(logit加算はkv全blankで無力→sink直行、
compressor/decompressor双方への設置)が正しかった。

## LogKV版 Selective本実験の結果 (2026-08-27, logkv-d512-logu, best ckpt 48100)
LogKVLM（[doc/logkv.md](../logkv.md)）、`exp/selective-copying/train.py --arch logkv`、
d512・2層・8ヘッド・5.26M、50k step、T~loguniform[1,2028]（旧系列と同一プロトコル）。

| T | pos_emb k4 | conv+sink k4 | **LogKV** (tok/str) |
|---|---|---|---|
| 2–10 | str 0.77–1.00 | str 0.97–1.00 | str 0.51–0.95 |
| 16 | 0.97 / 0.77 | 1.00 / 0.97 | 0.88 / 0.31 |
| 32–128 | tok 0.89–0.93 / str 0.39–0.56 | tok 0.98 / str 0.83–0.88 | tok 0.71–0.79 / str 0.02–0.11 |
| 1024 | 0.74 / 0.06 | 0.89 / 0.40 | 0.62 / 0.00 |
| 2048 (域端) | 0.65 / 0.02 | 0.84 / 0.27 | 0.59 / 0.00 |
| 16384 | 0.40 / 0 | 0.59 / 0.01 | 0.55 / 0 |
| 49152 | 0.24 | 0.39 | **0.46** |
| 98304–131072 | tok 0.17–0.18 | tok 0.28–0.30 | **tok 0.41–0.43** |

* **域内はconv版に大きく劣る**: 散在桁の検出・出現順の維持には局所特徴(conv)や検索窓
  (retrieve)の補助が効いており、位置補助ゼロのLogKVはstrが早く落ちる(T=32でstr 0.11)。
  tokは滑らかに減衰(0.88@16 → 0.59@2048)
* **超長域は全構成中最良**: 49k以降 tok 0.41–0.47で、conv+sink(0.28–0.39)を含む全旧構成を
  上回る。98k–131kのtok 0.41–0.43は**bag最適0.4121とほぼ一致** — LogKVは任意スケールで
  「内容(bag)」を保持し続け、失うのは「順序」だけ。旧構成はbag最適を大きく割り込む
  (内容ごと喪失)。Copyingと同じ「崖がない」プロファイル
* 答え位置別の正答率はT=8/16で中央位置(3–6)が最も低いU字型(系列位置効果) —
  失われるのが順序情報であることと整合
* **T=1異常がCopyingと完全に同一署名で再現**: str 0.137(Copying 0.133)、答え位置7・8のみ
  0.60/0.51(Copying 0.65/0.46)。独立訓練・別タスクで一致 → アーキテクチャ構造由来で確定。
  構造分析による有力仮説: T=1では答え位置s=16..19が「レベル1位相が同一(u=1, j=0)かつ
  レベル0窓が全マーカー」の縮退群を成し、s=18/19は窓内容(前層出力の多重集合)が
  {A,A,B,B}/{A,B,B,B}とほぼ区別不能になり「今何桁目か」が壊れる。s=16/17は窓に
  桁を含む位置(12,13)の特徴的な前層出力が残るため生存、s=20はj=1で位相が変わり生存。
  T≥2では答え位置がレベル位相をまたぐため衝突しない。位置7・8だけが失敗する
  観測と正確に対応する

## LogKV + 学習可能位相埋め込み版の結果 (2026-08-28, logkv-d512-logu-phase, best ckpt 49000)
Copyingを全域完全解にした位相埋め込み(`--phase-emb`, phase_levels=16)を同条件でSelectiveに適用。

| T | conv+sink k4 | LogKV 位相なし | **LogKV 位相** (tok/str) |
|---|---|---|---|
| 1 | 1.00 / 1.00 | 0.91 / 0.14 | **1.00 / 1.00** |
| 2–10 | str 0.97–1.00 | str 0.51–0.95 | str 0.88–0.996 |
| 16 | 1.00 / 0.97 | 0.88 / 0.31 | 0.97 / 0.78 |
| 64 | 0.98 / 0.86 | 0.76 / 0.04 | 0.90 / 0.38 |
| 512 | 0.93 / 0.62 | 0.64 / 0.01 | 0.77 / 0.06 |
| 1536 (域内) | 0.86 / 0.27 | 0.62 / 0.00 | 0.67 / 0.01 |
| **2048 (域外)** | 0.84 / 0.27 | 0.59 / 0.00 | **0.27 / 0.00** |
| 4096–131072 | tok 0.76→0.28 | tok 0.58→0.43 | **tok 0.24→0.15 (≈チャンス 0.125)** |

* **域内は大幅改善**(T=64: str 0.04→0.38、T=16: 0.31→0.78、T=1は完全回復)だがconv版には届かない。
  答え位置別正答率は依然U字型(T=512: 中央 0.46、端 1.00) — 順序符号としては部分的
* **訓練域を超えた瞬間に崩壊**: T=2048でtok 0.67→0.27、以降チャンス水準。位相なし版が
  bag最適(0.41)を保っていたのに対し、内容ごと取り出せなくなる
* 原因(診断): 位相埋め込みは絶対位置のC進数コードなので、**訓練で見なかった桁値のベクトルは
  未学習(初期値のまま)**。max_t=2028ではレベル5(1024の桁)は{0,1}、レベル6以上は常に0しか
  出現しない。T≥2029では答え位置自身の高位桁が未学習値になり、位相に依存した検索が
  壊れる。Copyingで無事だったのは、桁が常に位置0–9(低位桁のみ非零)にあり、クエリも
  高位桁を使わずに済んだため。Selectiveは散在桁の順序比較に高位桁まで使う学習をした結果、
  域外で成立しなくなった
* 含意: 絶対位置コードの外挿問題そのもの。対策候補は
  (a) `phase_levels`を訓練で全桁値が出現する範囲に制限(max_t=2028ならレベル≤5、周期1024。
      最小は2で周期16 = チャンク内/隣接チャンクの順序のみを与え長距離順序は階層構造に任せる)、
  (b) 訓練時に位相の起点をランダムシフトして全桁値を学習させる(augmentation)

| 16 | 1.00 / 0.97 | 0.88 / 0.31 | 0.97 / 0.78 | 0.98 / **0.81** | 0.96 / 0.66 |
| 32 | 0.99 / 0.88 | 0.79 / 0.11 | 0.93 / 0.48 | 0.94 / **0.61** | 0.88 / 0.31 |
| 64 | 0.98 / 0.86 | 0.76 / 0.04 | 0.90 / 0.38 | 0.90 / 0.37 | 0.81 / 0.11 |
| 512 | 0.93 / 0.62 | 0.64 / 0.01 | 0.77 / 0.06 | 0.75 / 0.03 | 0.69 / 0.02 |
| 2048 (域外) | 0.84 | 0.59 | **0.27** (崩壊) | 0.57 | **0.63** |

  (**エイリアシング**)
* **phase2**: 域内は位相なしとphase16の中間(T=64 str 0.11)だが、遠距離は全構成中最良
  (≥32kでtok 0.54–0.58、bag最適を全域で上回る = 順序情報を部分的に保持したまま64倍外挿)。
  周期16は訓練中から常時折り返すので、タグは局所順序にのみ使い長距離順序は階層構造に
  任せる学習になる
* 周期長は「域内の順序精度 ↔ 域外のエイリアシング耐性」のトレードオフ軸。
  Copyingは phase2 でも全域 1.000(桁位置0–9のタグは周期16でも一意)
* いずれの構成も域内ではconv+sink版(T=64 str 0.86)に届かない。散在桁の順序符号は
  依然として主弱点で、位相埋め込みは「縮退の解消」と「外挿を壊さない局所順序」までが守備範囲
