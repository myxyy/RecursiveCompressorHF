# やること
instructモデルを読み込み、ChatGPTのような対話インタフェースをWebUIで提供するサーバーとして機能するPythonコードを作成する

# 具体的内容
* ユーザがブラウザ上で入力した文章にBOSトークンと`[QUERY]`タグと`[ANSWER]`タグを付けた上でinstructモデルによる推論を行う  
* BOSトークンが出るまでを返答として、その時点での隠れ状態をブラウザのタブが閉じられるまで保持し、続きの会話は隠れ状態を起点に同様の処理を行う  
  - ブラウザの動作に対して詳しくないためこのあたり他に良い方法があれば提案お願いします（タイムアウトとか）
  - 複数タブや複数マシンからのアクセスにおいてはそれぞれの隠れ状態は独立に保持するようにしたい
    + 推論中に別セッション？からのリクエストがあった場合は推論終わってから対応
* ユーザーはtemperature (0.01~2)、top-p (0~1)をスライダーで設定できる
* コンテキスト長については会話1ターンの返答の上限を1024とするが、マルチターンの継続で消費されるコンテキストは無制限とする
  - 理論上VRAM不足で落ちる場合はあるが、コンテキスト長に対して対数増加のため実用上発生しないものとして扱う
* モデル重みはHuggingFaceの`myxy/recursive-compressor-2-7b-instruct`レポジトリから`from_pretrained()`でダウンロードして用いる
* モデル重みはサーバー立ち上げ時に保持して、隠れ状態とコンテキストだけ適宜入れ替えて使用する
* デフォルトポートは適当に決めて、必要であればコマンドライン引数で設定できるようにしたい

# 設計方針 (Claude追記)
* **フレームワーク**: FastAPI + uvicorn、フロントエンドはHTML/JS/CSSを単一ファイルにベタ書きしたものをサーバーから配信
* **セッション管理**: WebSocketコネクション単位でセッションを管理
  - ブラウザタブごとに `/ws/chat` への独立したWebSocket接続を張る
  - 接続中はサーバー側に隠れ状態 (`hidden`) を保持
  - WebSocket切断 = タブ閉鎖/リロード/ナビゲーションとして扱い、隠れ状態を破棄
  - idle timeoutやcookie/sessionIDが不要、確実かつシンプル
* **逐次推論**: グローバルな `threading.Lock` で推論を排他化
  - 推論中の他リクエストはロック待ちで自動的にキューイング
  - 別セッションからのリクエストは現在の推論完了後に処理される
* **生成ループ**: HuggingFace `generate()` ではなく `model.step()` を直接使う独自ループを実装
  - 理由: turn 2以降は「既存hidden + 新規クエリ複数トークン」を渡す必要があるが、現状の `prepare_inputs_for_generation` がpast_key_valuesがあれば最終1トークンのみに絞る実装になっており、`generate()` ではこの形を扱いづらい
  - 独自ループならBOS停止条件、ストリーミング、ターン上限トークン数を素直に書ける
* **会話フォーマット** (`step()` に流すトークン列が学習時と一致するように):
  - ターン1: `<s>[QUERY]q1[ANSWER]` を `step` に流して a1 を生成
  - 生成中: モデルが `<s>` (BOS) を出した時点で停止。ただしBOS自身も `step` に流して隠れ状態に取り込んでから停止する
  - ターン2: `[QUERY]q2[ANSWER]` のみを `step` に流す (BOSは前ターン末尾で取り込み済み)
  - 全ターンで `step` に流したトークンを連結すると `<s>[QUERY]q1[ANSWER]a1<s>[QUERY]q2[ANSWER]a2<s>...` となり学習時フォーマットと一致
* **ストリーミング**: 推論スレッド → `asyncio.Queue` → WebSocket でトークンをリアルタイム送信
  - 部分トークンのデコード崩れ対策として、累積デコード済み文字列との差分を都度送る方式
* **ポート**: デフォルト 8000、`--port` で変更可
* **依存追加**: `fastapi`, `uvicorn[standard]` (`uv add` 必要)
