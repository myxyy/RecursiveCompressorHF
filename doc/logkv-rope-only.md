# phase2を無効にした局所RoPEの比較

## 状態と範囲

2026-09-09、前回のphase2＋局所RoPEからphase2を除く比較を開始した。
実験準備commitは`8b99ddf`、Copying開始は21:16:28 JST。
読み出し側RoPEのみ、Compressor側RoPEのみの2条件を、Copying/Selective Copyingで独立に学習する。
両RoPEの同時導入は今回の範囲に含めない。
実装は前回と同じ凍結source `afaea2b1d8b0bbc6e91aba25e1b9a3594297875b`を使い、モデルコードに変更はない。
Copyingは9月10日01:05:11 JSTに完了（約3時間49分）し、132評価セルの保存結果を確認した。
その時点の全体予測は約7.66時間で上限8時間未満だったため、01:05:14 JSTにSelectiveを開始した。
Selectiveも9月10日04:52:45 JSTに学習・評価を完了し、04:52:48 JSTにCPU自動集計まで終了した。
全4 runの経過時間は約7時間36分で、8時間上限内。全GPU解放済み、追加実験は起動していない。

最大2 GPU（GPU 1が読み出し側、GPU 0がCompressor側）で、Copyingの終了・検証後にSelectiveへ進む。
対応する前回4 runの実時間から、全体で約7時間45分と見積もる。
**4 run・両タスク全体に8時間の上限**を設ける。
Copying終了時に、経過時間＋Selective見積もりが8時間以上なら、Selectiveを起動せず確認待ちにする。
推定式は`Copying実時間 × (前回Selective読み出し時間 / 前回Copying読み出し時間) + 0.10時間`。
実行中に全体の8時間上限へ達した場合や、run/検証が失敗した場合も停止し、自動再試行しない。
16M評価とmainマージは保留を維持する。

**phase2なしでも読み出しRoPEは高精度に学習できたが、全評価点での完全一致は未達。Compressor側RoPEのみは長距離で大きく低下した。**

読み出しRoPEのbest（48,700 steps）は全33点で完全一致率98.4375〜100%、うち12点で256/256。

今回評価したT4096/8192では見られない。ただし境界を1刻みで再評価したわけではない。

Compressor RoPEのbest（47,700 steps）とfinalはT64で43.75/41.41%、T1024で両方0.78%。
T2048/4096/8192では両方0/256となった。T8192の桁正答率は58.01/55.55%で、
「全10桁の同時正解だけをわずかに逃している」状態ではない。短距離にもT9で0/256などの失敗がある。

読み出しRoPEのみはT64で53/256（best）、31/256（final）。T1024では両方5/256、
T2048では両方2/256、T4096・8192では両方0/256だった。
T8192の桁正答率は49.69% / 49.45%であり、完全一致0%を「すべての桁を失った」とは解釈しない。
Compressor RoPEのみはT16ですでに9/256 / 3/256、表に示したT64以上の各点では両checkpointとも0/256だった。

**phase2を外すことによる明確なSelective改善は確認できなかった。**
読み出しRoPEでは短距離T16の精度が下がり、T64はbestで低下・finalで上昇する。
T256・1024など上回る点もあるが、長距離の完全一致は未解決で、一方向の改善ではない。
Compressor RoPEのみの大きな低下は、この構成でphase2を代替する方針を支持しない。

Copyingでは読み出しRoPEのみでT131072まで高い精度が出た一方、Selectiveは学習範囲内のT1024でも完全一致が少ない。
したがって今回のSelectiveの難しさは、学習範囲を超える距離だけでは説明できない。
ただし、選択・順序保持・圧縮・読み出しのどこが主因かを切り分けた診断ではない。
CopyingとSelectiveは別々の学習済みモデルなので、同一モデルの能力差を測定した結果でもない。

各条件1学習seedで、phase2除去に伴う共通初期重みの差もある。
この制約のもとでは、Copyingの完全一致を優先する土台としてphase2を維持する判断を覆す結果ではない。
両RoPE併用や追加学習、長距離Selectiveの追加評価は行っていない。

## 条件

| 項目 | 設定 |
|---|---|
| phase embedding | false。`--phase-emb`を指定しない。各層の実際のphase_levelsは0 |
| RoPE | `--retrieval-rope`または`--compressor-rope`の片方のみ |
| 固定減衰 | `−i log C`を維持（level_decay_scale=1） |
| その他 | gated attention、self slot。相対K/V、子位置K/V変換、scalar bias、compressor decay、KV/V normは無効 |
| サイズ | d512、8 heads、d_ff1024、2層、C4、5,786,112 parameters |
| タスク | 固定M=10、追加prefixなし。CopyingとSelectiveは別モデル・別データ生成器 |
| 学習 | 50,000 steps、batch64、grad accumulation1、T~loguniform[1,2028]、全位置CE |
| 最適化 | AdamW、lr3e−4、warmup1000、weight decay0、gradient clip1 |
| seed | 学習0、データ1、評価12345 |
| 精度 | 学習fp32重み＋bf16 autocast、評価bf16重み＋autocast |
| 評価 | best/final各33点、T=1〜14と16〜8192の2の冪・中間点、各256例 |
| best選択 | 従来どおり訓練100 steps区間のstring/token/−EMA loss |

phase2以外の学習条件は前回の[局所RoPE比較](logkv-phase2-rope.md)と同じ。
前回のphase2あり結果を保存済み対照として使い、同じTとcheckpoint種別で比較する。
各条件1学習seedであり、今回の数値だけで再現性を保証しない。

## 事前確認と比較上の制約

CPUで実際のconfigと全層のphase無効化、有限なforward出力を確認した。
RoPEの2方式間では初期重みが完全一致し、同一タスク内の学習データ列も同じになる。
一方、phase2の除去はパラメータを8,192個減らし、初期化時の乱数消費も変える。
事前確認ではphase2ありとの共通テンソル16個に初期値の差があった。
したがって前回との比較は学習設定を揃えた性能比較であり、共通初期重みを固定した因果実験ではない。
既存の実装テスト265件は前回成功済み。今回モデルコードを変更していないため再実行していない。
